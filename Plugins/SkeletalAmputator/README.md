# Skeletal Amputator

`SliceMesh` принимает плоскость в мировых координатах. Разделение выполняется по треугольникам текущей позы независимо от пересечения костей. Каждая сторона плоскости разделяется на самостоятельные фрагменты по связности геометрии и сохранившимся цепочкам костей. Оболочки брони и тела, связанные общей цепочкой костей на этой стороне, остаются вместе. Отделённые кисти получают собственные компоненты, меши, скелеты и Physics Asset. Исходный компонент получает положительный фрагмент с наибольшим числом треугольников. Все части включают физику и поддерживают повторный разрез. Событие OnSliceMesh отправляется один раз после создания всех частей. Если построение не удалось, исходный меш сохраняется.

Контуры среза триангулируются constrained Delaunay с нечётным правилом заполнения. Вложенные полости сохраняются, отдельные контуры не соединяются перемычками. Для пересечённых сегментов костей создаются граничные точки нового reference skeleton; однокостные фрагменты сохраняют кость даже при отсутствии пересечения её оси. Поза фиксируется в новом reference pose, а веса переназначаются и нормализуются.

Внутренняя геометрия использует порядок вершин с внешней нормалью по векторному произведению. При чтении и записи render buffers порядок переводится в соглашение Unreal о лицевой стороне. Нормали среза направлены наружу каждой части; материал остаётся односторонним. Сквозные тесты проверяют согласованность порядка индексов и нормалей готового меша.

## Демонстрация в редакторе

Карта `/Game/Test/TestSlice/SkeletalAmputatorDemo` содержит Blueprint `/Game/Test/TestSlice/BP_SkeletalAmputatorDemo` на основе Actor с компонентами `SliceableMesh` и `CutPlane` (Arrow). Назначен существующий Skeletal Mesh `Worm` и материал `M_SkeletalSliceInterior`; исходная физика выключена. В Event Graph: BeginPlay → Delay 2 секунды → Slice Mesh. Make Plane From Point And Normal получает Get World Location и Get Forward Vector стрелки. При Play обе части переходят в физику и падают на пол. Для изменения разреза переместите или поверните `CutPlane`, затем запустите Play заново.

## Материал среза

Материал по умолчанию — `Content/Materials/M_SkeletalSliceInterior.uasset`. Цвет вычисляется по расстоянию от пикселя до сегментов скелета. Вершины среза передают исходную локальную позицию через UV1.xy и UV2.x; UV0 содержит координаты в плоскости среза. Старые срезы сохраняют свои UV и материал при последующем разделении.

Параметры компонента: `TissueColor`, `BoneColor`, `BoneRadius` в сантиметрах. Для единственной кости без дочерних костей `TerminalBoneLength` задаёт длину сегмента вдоль её локальной оси X; одна точка скелета сама по себе длину не определяет.

Пользовательский материал получает параметры `TissueColor`, `BoneColor`, `BoneRadius`, `BoneCount` и `BoneSegments`. Последний — линейная float4-текстура шириной 2 и высотой по числу сегментов: первый пиксель строки содержит начало, второй — конец в локальных координатах позы разреза. Текстура использует точечную фильтрацию. Пиксель вне радиуса всех сегментов остаётся цветом ткани.

## Физика

Для каждой физической кости строится выпуклая коллизия из геометрии её части. Плоские и пустые наборы не создают невалидных convex-тел; геометрия и веса передаются соответствующему объёмному телу. Сохраняемые суставы получают преобразованные локальные системы координат. Таблица запрещённых столкновений использует индексы новых тел. Дополнительно отключаются столкновения тел, совместно влияющих на одну вершину.

Новые тела используют 16 позиционных и 4 скоростных итерации, линейное демпфирование 0,1 и угловое 0,5. Выпуклая коллизия является приближением поверхности; вогнутости одного физического тела она не воспроизводит.

## Границы реализации

Результирующие части используют LOD0; анимационная поза фиксируется перед переходом в ragdoll. Анимационные Blueprint, cloth и morph targets не переносятся как редактируемые системы. Некорректные открытые или неманифолдные контуры среза отклоняются. Проверенные примеры не доказывают корректность любых импортированных ассетов: дополнительные модели должны проходить те же геометрические и физические проверки.

## Несколько фрагментов и профилирование

`FSliceResult.PositiveFragments` и `NegativeFragments` содержат все компоненты соответствующей стороны. Старые поля `PSideSkeletalMeshComp` и `NSideSkeletalMeshComp` сохранены и указывают только на первый фрагмент каждой стороны. Blueprint, обрабатывающие все части, должны обходить новые массивы.

Генератор включён в модуль SkeletalAmputator как `FAPSkeletalMeshGenerator`. Зависимость от RuntimeSkeletalMeshGenerator удалена. Перенесены `Private/APSkeletalMeshGenerator.h` и `.cpp`; MIT-лицензия сохранена в `ThirdParty/RuntimeSkeletalMeshGenerator/LICENSE`. Старый плагин остаётся в проекте для отдельного тестового актора BattleSymphony.

CPU Trace-события имеют префикс `SkeletalAmputator_`. Главный scope — `SliceMesh`. Вложенные события измеряют получение позы, извлечение геометрии, clipping, триангуляцию, самопересечения, разделение на фрагменты, генерацию мешей, convex cooking, ожидание рендера, инициализацию ресурсов, установку компонентов и вызов обработчиков результата.

Начать запись из консоли редактора:

```text
Trace.Stop
Trace.File M:/BattleSymphony/Saved/SkeletalAmputator.utrace cpu,frame,bookmark
```

После разреза завершить запись:

```text
Trace.Stop
```

Открыть файл в Unreal Insights и найти `SkeletalAmputator_SliceMesh` в Timing Insights на GameThread. Inclusive Time включает вложенные этапы, Exclusive Time исключает их. `CookConvexBody` записывается отдельно для каждого физического тела. Сравнивать время следует в одинаковых конфигурациях сборки.

## Ограниченный разрез

Blueprint-вызов `Slice Mesh In Radius` принимает `Slice Center`, `Slice Normal` в мировых координатах и `Slice Radius` в сантиметрах (по умолчанию 25). Центр лежит в плоскости среза. Радиус выбирает пересечения сегментов parent–child скелета с этой плоскостью; выбранная ветвь отсекается целиком с закрытым срезом. Это радиус отбора костей, а не вырезание круглой дырки в поверхности.

Если ни один сегмент кости не пересечён внутри радиуса, меш не заменяется, физика не включается и событие разреза не отправляется. Касание кости концом или совпадение её оси с плоскостью не считается пересечением. Без сегментов parent–child этот режим разрез не выполняет. `TerminalBoneLength` описывает визуализацию внутреннего материала и не создаёт настоящих костей.

В ограниченном режиме исходный компонент сохраняет оставшееся тело. В `PositiveFragments` находится оставшаяся часть, в `NegativeFragments` — отделённые части; эти массивы описывают назначение частей, поскольку оставшееся тело может лежать с обеих сторон плоскости. Обычный `Slice Mesh` сохраняет прежнюю семантику бесконечной плоскости.

Для Arrow-компонента передайте Get World Location в Slice Center, Get Forward Vector в Slice Normal, затем задайте радиус так, чтобы в область попала только нужная конечность. Отсутствующие в радиусе разрезы восстанавливаются из исходных треугольников без дополнительных крышек. В Trace добавлены `SelectBonesInRadius` и `RecombineLimitedSlice`.

Для демонстрации ограниченного разреза подготовлены `BP_LimitedSliceDemo` и карта `/Game/Test/TestSlice/LimitedSkeletalAmputatorDemo`. Через две секунды после BeginPlay Blueprint рассчитывает плоскость между `lowerarm_l` и `hand_l` и вызывает новый узел с радиусом 12 см.

Для импортированных моделей добавлены сценарии `Mannequin.LimitedArm` и `Quinn.LimitedArm`: попадание только в поверхность без кости, отделение одной конечности, независимые скелеты и физика, падение и повторный ограниченный разрез противоположной руки. При группировке геометрии соседние кости ищутся по иерархии скелета; пространственная близость другой части лежащего тела сама по себе не связывает фрагменты. Открытые контуры вне выбранной области могут быть отброшены при промежуточном построении крышек, но итоговая граница выбранного среза обязана быть замкнутой.

## Поиск разрезаемых компонентов в мире и результаты

`Slice Mesh In Radius` возвращает `FSliceResult`. Поле `Success` равно true только после установки фрагментов; `Source Component` указывает на исходный компонент. `Positive Fragments` содержит оставшуюся часть, `Negative Fragments` — отделённые части. При промахе или отказе геометрической проверки возвращается пустой результат с `Success = false`, событие `OnSliceMesh` не вызывается. При успехе событие и возврат функции содержат одинаковый результат.

`Slice Meshes In Radius` из `APSkeletalSliceLibrary` принимает те же центр, нормаль и радиус, но не требует Target. Мир определяется скрытым World Context из вызывающего Blueprint. Узел ищет зарегистрированные `APSliceableSkeletalMeshComponent` в этом мире, независимо от настроек коллизии, и возвращает массив только успешных результатов. Обычный `SkeletalMeshComponent` и версия Old не участвуют. Список кандидатов фиксируется до первой операции, поэтому вновь созданные части не режутся повторно в рамках того же вызова. Пустая область и некорректные параметры дают пустой массив.

Для Blueprint используйте `Break Slice Result`, а для универсального узла сначала `For Each Loop` по возвращённому массиву. Существующие подключения исполнения компонентного узла сохраняются; при необходимости обновите узел через Refresh Node для появления выходного пина.
